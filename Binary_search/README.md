## Бинарный поиск

**Описание задачи**
- Дана последовательность из "N" целых чисел, отсортированная по неубыванию:
```
a[0] ≤ a[1] ≤ ... ≤ a[N-1]
```
- Необходимо проверить, содержится ли заданное число "target" в последовательности.
- Требуется реализовать бинарный поиск с временной сложностью "O(log N)".

---

Формат входных данных
```
N
a[0]
a[1]
...
a[N-1]
target
```
где:

- "N" — количество элементов;
- "a[i]" — элементы отсортированной последовательности;
- "target" — искомое число.

---

Формат выходных данных
- Если "target" найден: YES
- иначе: NO

---

# Алгоритм

Бинарный поиск работает за счёт того, что последовательность отсортирована.

Используются две границы:
```
int left = 0;
int right = n - 1;
```
На каждой итерации вычисляется середина диапазона:
```
int mid = left + (right - left) / 2;
```
Затем "arr[mid]" сравнивается с "target".

**Возможные случаи**

Элементы равны: `arr[mid] == target`. Число найдено, выводим "YES".

Средний элемент меньше искомого: `arr[mid] < target`

Искомое значение может находиться только справа: `left = mid + 1;`

Средний элемент больше искомого: `arr[mid] > target`

Искомое значение может находиться только слева: `right = mid - 1;`

Поиск продолжается, пока: `left <= right`

Если границы пересеклись, элемент отсутствует.

---

# Пример работы

Массив: `-99 -94 -85 -82 -52 -39 -39 -20 -10 56`

Ищем: `-39`

|Шаг| "left"| "right"| "mid"| "arr[mid]"| Действие|
|---|-------|--------|------|-----------|---------|
1| 0| 9| 4| -52| искать справа
2| 5| 9| 7| -20| искать слева
3| 5| 6| 5| -39| найден

Результат: `YES`

---

Почему используется "left + (right - left) / 2"

Вместо: `(left + right) / 2`

используется: `left + (right - left) / 2`

Такая запись позволяет избежать переполнения при сложении больших значений "left" и "right".

---

# Реализация

Для хранения последовательности используется динамический массив "std::unique_ptr":

auto arr = std::make_unique<int[]>(n);

Память автоматически освобождается после завершения работы программы.

# Сложность

На каждой итерации диапазон поиска уменьшается примерно в два раза.

Поэтому:

|Показатель| Сложность|
|----------|----------|
Время поиска| "O(log N)"
Дополнительная память поиска| "O(1)"
Память для массива| "O(N)"

Для сравнения, линейный поиск имеет сложность "O(N)".

---

# Ограничение

Бинарный поиск требует отсортированную последовательность.
- Для: `1 5 9 15 20` алгоритм работает корректно.
- Для: `1 15 5 20 9` использовать бинарный поиск нельзя, поскольку порядок элементов не позволяет определить, в какой половине находится искомое значение.

---

# Итог

Решение использует итеративный бинарный поиск. За "O(log N)" оно определяет, присутствует ли заданное число в отсортированной последовательности, и выводит "YES" или "NO".
