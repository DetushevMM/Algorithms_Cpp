# Очередь на двух стеках

## 1. Описание задачи

Необходимо реализовать структуру данных очередь (Queue), используя два стека.

Очередь должна поддерживать следующие операции:

| Метод | Назначение |
|---|---|
| Push(element) | Добавить элемент в конец очереди |
| Pop() | Удалить первый элемент очереди |
| Top() | Получить первый элемент очереди без удаления |
| IsEmpty() | Проверить, пуста ли очередь |

Затем реализованная очередь используется для моделирования очереди в поликлинике.

Система принимает две основные команды:

- новичок: — после команды вводится имя нового человека, который становится в конец очереди;
- следующий — первый человек в очереди отправляется к врачу.

Работа также может быть завершена командой:

`text
Смена закончилась!

Если при выполнении команды следующий очередь пуста, программа выводит:

Все вылечены!

---

2. Основная идея

Очередь должна работать по принципу FIFO (First In, First Out):

> Первый пришёл — первый вышел.

Например:
```
Push(A)
Push(B)
Push(C)
```
очередь выглядит так:
```
Начало                    Конец
  ↓                         ↓
[A] [B] [C]
```
При выполнении: Pop() - первым будет удалён A.

Однако обычный стек работает по противоположному принципу LIFO:

> Последним пришёл — первым вышел.

Поэтому для реализации FIFO используются два стека.

3. Стек Stack<T>

Для реализации очереди сначала создаётся универсальный шаблонный класс:
```
template <class T>
class Stack
```
Стек хранит элементы в динамическом массиве.

Основные поля:
```
T* data_;
int capacity_;
int top_;

data_ - Указатель на динамический массив, в котором хранятся элементы.
capacity_ - Текущая вместимость массива.
```
Начальное значение:
- capacity_ = 10 - При заполнении массива его вместимость увеличивается в два раза. 
- top_ - Индекс верхнего элемента стека.

В пустом стеке: top_ = -1

Например:
```
data_ = [A] [B] [C] [ ] [ ]
                   ↑
                 top_
```
Здесь: top_ = 2

---

4. Операции стека

4.1. Push()

Добавляет элемент на вершину стека.

Алгоритм:
1. Проверить, достаточно ли места.
2. Если массив заполнен — увеличить его размер в два раза.
3. Увеличить top_.
4. Записать элемент в новую позицию.
```
void Push(const T& elem) {
  if (top_ + 1 >= capacity_) {
    capacity_ *= 2;

    T* new_data = new T[capacity_];

    for (int i = 0; i <= top_; ++i) {
      new_data[i] = data_[i];
    }

    delete[] data_;
    data_ = new_data;
  }

  data_[++top_] = elem;
}
```
Амортизированная сложность: O(1)

---

4.2. Pop()

Удаляет верхний элемент.

Физически элемент из массива не стирается. Вместо этого уменьшается значение top_.
```
void Pop() {
  if (!IsEmpty()) {
    --top_;
  }
}
```
Сложность: O(1)

---

4.3. Top()

Возвращает верхний элемент:
```
T Top() const {
  return data_[top_];
}
```
Сложность: O(1)

---

4.4. IsEmpty()

Проверяет, пуст ли стек:
```
bool IsEmpty() const {
  return top_ == -1;
}
```
Сложность: O(1)

---

5. Очередь на двух стеках

Класс Queue<T> содержит два стека:
```
Stack<T> input_stack_;
Stack<T> output_stack_;
```
Они выполняют разные функции.

Стек Назначение
```
input_stack_ Приём новых элементов
output_stack_ Выдача элементов из очереди
```
Новые элементы всегда добавляются в input_stack_.

Удаление происходит из output_stack_.

---

6. Почему нужны два стека

Рассмотрим добавление трёх элементов:
```
Push(A)
Push(B)
Push(C)
```
Все они попадают в input_stack_:
```
input_stack_

[C] ← вершина
[B]
[A]
```
Если просто выполнить Pop(), первым будет получен C.

Это нарушает принцип очереди FIFO.

Необходимо изменить порядок элементов:
```
A B C
↓
C B A
```
Первый стек переворачивает порядок один раз, а второй стек переворачивает его ещё раз.

В результате:
```
output_stack_

[A] ← вершина
[B]
[C]
```
Теперь A можно извлечь первым.

---

7. Метод Transfer()

Перенос элементов между стеками выполняется методом:

void Transfer()
Его задача — полностью перенести элементы из input_stack_ в output_stack_.

Алгоритм:
```
while (!input_stack_.IsEmpty()) {
  output_stack_.Push(input_stack_.Top());
  input_stack_.Pop();
}
```
Рассмотрим:
```
input_stack_:

[C] ← вершина
[B]
[A]
```
После Transfer():
```
input_stack_:       output_stack_:

                    [A] ← вершина
                    [B]
                    [C]
```
Порядок элементов восстановлен для работы очереди FIFO.

---

8. Важное правило Transfer()

Transfer() вызывается только тогда, когда output_stack_ пуст.

Это ключевой принцип реализации.

Например:
```
input_stack_:  [D]

output_stack_: [C]
               [B] ← вершина
```
В очереди: A → B → C → D

B и C должны быть обработаны раньше D.

Поэтому нельзя переносить D в output_stack_, пока там остаются B и C.

Если output_stack_ не пуст, его элементы всегда старше элементов input_stack_.

---

9. Метод Queue::Push()

Новый элемент всегда добавляется в input_stack_:
```
void Push(const T& element) {
  input_stack_.Push(element);
}
```
Например:
```
Push(A)
Push(B)
Push(C)
```
получаем:
```
input_stack_:

[C]
[B]
[A]
```
---

10. Метод Queue::Top()

Перед получением первого элемента проверяется output_stack_.

Если он пуст:
```
if (output_stack_.IsEmpty()) {
  Transfer();
}
```
После этого верхний элемент output_stack_ является первым элементом очереди.
```
return output_stack_.Top();
```
Таким образом:
```
Queue:
A → B → C
output_stack_:

[A] ← Top()
[B]
[C]
```
Top() возвращает A.

---

11. Метод Queue::Pop()

Алгоритм удаления элемента:
1. Проверить output_stack_.
2. Если он пуст — выполнить Transfer().
3. Если после этого стек не пуст — удалить его верхний элемент.
```
void Pop() {
  if (output_stack_.IsEmpty()) {
    Transfer();
  }

  if (!output_stack_.IsEmpty()) {
    output_stack_.Pop();
  }
}
```
Например:
```
output_stack_:

[A] ← вершина
[B]
[C]
```
После Pop():
```
output_stack_:

[B] ← вершина
[C]
```
Следующим будет B.

---

12. Метод Queue::IsEmpty()

Очередь считается пустой только тогда, когда пусты оба стека:
```
bool IsEmpty() const {
  return input_stack_.IsEmpty() &&
         output_stack_.IsEmpty();
}
```
То есть:
```
input_stack_  = пуст
output_stack_ = пуст
        ↓
Queue = пустая
```
Если хотя бы один из стеков содержит элементы, очередь не пуста.

---

13. Амортизированная сложность

На первый взгляд Transfer() может показаться дорогой операцией.

Если в input_stack_ находится N элементов, перенос всех элементов занимает: O(N)

Однако каждый элемент переносится из input_stack_ в output_stack_ не более одного раза за время его нахождения в очереди.

Например:
```
Push(A)
Push(B)
Push(C)
```
Затем выполняется первый Pop():
```
input → output

A переносится один раз
B переносится один раз
C переносится один раз
```
После этого элементы удаляются непосредственно из output_stack_.

Если позже добавляется: Push(D)

D остаётся в input_stack_, пока output_stack_ не опустеет.

Поэтому для последовательности из N операций суммарная стоимость всех переносов составляет O(N).

Амортизированная сложность операций очереди:
```
Push()      O(1)
Pop()       O(1) амортизированно
Top()       O(1) амортизированно
IsEmpty()   O(1)
```
Отдельный вызов Transfer() может иметь сложность O(N), но такие операции не выполняются для каждого элемента многократно.

14. Работа основной программы

1. Основная программа создаёт очередь строк: `Queue<std::string> queue;`
Поэтому в качестве элементов очереди используются имена людей.
2. Затем программа построчно считывает команды:
```
while (std::getline(std::cin, command))
```
Поддерживаются три варианта действий.

---

14.1. Команда новичок:

После команды считывается имя:
```
std::string name;
std::cin >> name;
queue.Push(name);
```
Новый человек добавляется в конец очереди.

Например:
```
новичок:
Ваня
новичок:
Петя
новичок:
Вася
```
Состояние очереди: Ваня → Петя → Вася

---

14.2. Команда следующий

Сначала проверяется, есть ли кто-нибудь в очереди:
```
if (queue.IsEmpty()) {
  std::cout << "Все вылечены!\n";
  return 0;
}
```
Если очередь не пуста:
1. Получается первый человек через Top().
2. Его имя выводится.
3. Он удаляется через Pop().
```
std::cout << queue.Top() << '\n';
queue.Pop();
```

14.3. Команда Смена закончилась!

При получении команды: Смена закончилась!

цикл обработки завершается:
```
if (command == "Смена закончилась!") {
  break;
}
```
При этом дополнительных сообщений программа не выводит.

15. Условие Все вылечены!

Сообщение: "Все вылечены!" выводится в двух случаях.
- Случай 1 — команда следующий при пустой очереди
 - Например: следующий когда в очереди никого нет. Результат: Все вылечены!
- Случай 2 — после обслуживания последнего человека. 
 - Если команда следующий удаляет последнего человека:
```
queue.Pop();

if (queue.IsEmpty()) {
  std::cout << "Все вылечены!\n";
  return 0;
}
```
программа сразу сообщает: "Все вылечены!" и завершает работу.

18. Схема работы очереди

Общий процесс можно представить следующим образом:
```
Push
                  │
                  ▼
          ┌───────────────┐
          │ input_stack   │
          └───────┬───────┘
                  │
                  │ Transfer
                  │ только если
                  │ output пуст
                  ▼
          ┌───────────────┐
          │ output_stack  │
          └───────┬───────┘
                  │
                  ▼
             Pop / Top
                  │
                  ▼
            Первый элемент
             очереди FIFO
```
---

19. Управление памятью

Оба стека используют динамические массивы: `data_ = new T[capacity_];`

При увеличении массива создаётся новый массив, элементы копируются, а старый освобождается: delete[] data_;

В деструкторе каждого Stack память также освобождается:
```
~Stack() {
  delete[] data_;
}
```
Поскольку Queue содержит два объекта Stack, при уничтожении очереди автоматически вызываются деструкторы обоих стеков.

20. Сложность алгоритмов

Пусть n — количество элементов в очереди.

|Операция| Временная| сложность| Пояснение|
|--------|----------|----------|---------|
Stack::Push()| O(1)| амортизированно| При расширении массива — O(n)
Stack::Pop()| O(1)| Изменяется только| top_
Stack::Top()| O(1)| Доступ к вершине массива
Stack::IsEmpty()| O(1)| Проверка top_
Queue::Push()| O(1)| амортизированно| Добавление в input_stack_
Queue::Pop()| O(1)| амортизированно| Возможен Transfer()
Queue::Top()| O(1)| амортизированно| Возможен Transfer()
Queue::IsEmpty()| O(1)| Проверяются два стека
Transfer()| O(n)| Перенос всех элементов


Для последовательности из большого количества операций работы с очередью амортизированная стоимость Push, Pop и Top составляет O(1).

---

21. Память

Очередь хранит каждый элемент только один раз логически, однако во время Transfer() элементы временно находятся в процессе копирования из одного динамического массива в другой.

Основная асимптотическая оценка памяти: O(n), где n — количество элементов очереди.

---

22. Итог

В задаче реализована очередь FIFO с использованием двух стеков LIFO.

**Основной принцип:**
```
input_stack
    ↓
  перенос
    ↓
output_stack
    ↓
  удаление
```
1. Новые элементы всегда поступают в input_stack_.
2. Элементы выдаются из output_stack_.
3. Перенос выполняется только тогда, когда output_stack_ пуст. Благодаря этому элементы, которые пришли раньше, всегда обслуживаются раньше новых.

Таким образом, два стека позволяют получить поведение очереди: Первый пришёл → первый обслужен

Для моделирования поликлиники:
```
"новичок:" → добавить человека в конец очереди
"следующий" → обслужить первого человека
"Смена закончилась!" → завершить работу
```
Если после обслуживания очередь становится пустой, программа выводит: `Все вылечены!`

Итоговая амортизированная сложность основных операций очереди:
```
Push()      O(1)
Pop()       O(1)
Top()       O(1)
IsEmpty()   O(1)
```
при использовании O(n) памяти.
