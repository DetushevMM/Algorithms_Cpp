# Задача «Авария в компьютерной сети» 

## Условие задачи

В компании установлено N компьютеров, соединённых двусторонними каналами связи.

На компьютере S появился вирус. Если заражённый компьютер соединён каналом с незаражённым работающим компьютером, вирус может перейти на него.

Некоторые компьютеры были вовремя отключены от сети. Через отключённый компьютер вирус распространяться не может.

- Необходимо определить, сколько работающих компьютеров окажутся заражены, включая компьютер S.
- Гарантируется, что компьютер S не отключён.

Формат ввода
- Первая строка: N M S — количество компьютеров, количество соединений, номер заражённого компьютера.
- Следующие M строк: пары u v — двусторонние соединения между компьютерами.
- Далее: число K — количество отключённых компьютеров.
- Если K > 0, следующая строка содержит K различных номеров отключённых компьютеров. Если K = 0, строка отсутствует.

Формат вывода:
- Одно целое число — количество компьютеров, которые окажутся заражены.

Ограничения
```
· 1 ≤ N ≤ 1000
· 0 ≤ M ≤ 5000
· 0 ≤ K < N
· Петель и кратных соединений нет.
```
---

### Идея решения

Задача сводится к поиску компоненты связности в графе компьютеров, содержащей вершину S, с одним важным условием: отключённые компьютеры не участвуют в распространении вируса. Их можно рассматривать как «удалённые» вершины, которые нельзя посещать.

Иными словами, нужно найти количество вершин, достижимых из S по рёбрам графа, исключая отключённые компьютеры.

---

## Алгоритм (DFS — обход в глубину)

Используется итеративный DFS с ручным стеком (без рекурсии — чтобы избежать переполнения стека вызовов при больших N и не зависеть от системных ограничений).

Шаги алгоритма:
1. Считываем граф и сохраняем его в матрице смежности massive[N+1][N+1].
2. Считываем список отключённых компьютеров и отмечаем их в массиве off[N+1].
3. Инициализируем массив посещённых visited[N+1] = false и стек stack[N].
4. Помещаем S в стек и отмечаем как посещённый.
5. Пока стек не пуст:
   - Извлекаем вершину cur из стека.
   - Увеличиваем счётчик заражённых.
   - Просматриваем всех соседей v вершины cur:
     - Если massive[cur][v] == true, v не посещён и v не отключён → добавляем v в стек и помечаем посещённым.
6. Выводим счётчик.

**Ключевой момент**

Проверка !off[v] не позволяет вирусу пройти через отключённый компьютер — такая вершина просто не попадает в стек и не увеличивает счётчик.

---

## Оценка сложности

|Параметр| Значение| Пояснение|
|--------|---------|----------|
Время| O(N²)| Каждая из N вершин просматривает всех N соседей в матрице смежности
Память| O(N²)| Матрица смежности размером (N+1) × (N+1)
Доп. память| O(N)| Массивы visited, off, stack

При N = 1000:
- Матрица смежности: 1001 × 1001 булевых значений ≈ 1 МБ.
- Время: ~10⁶ операций — мгновенно.

---

## Почему выбраны vector/массивы и матрица смежности

Хотя условие позволяет использовать vector и array, в данном решении применяются статические массивы — и вот почему это оправдано:

1. Матрица смежности vs список смежности

|Критерий| Матрица смежности| Список смежности|
|--------|------------------|-----------------|
Память| O(N²) ≈ 1 МБ при N=1000| O(N + M) ≈ меньше
Проверка ребра| O(1)| O(deg(v))
Обход всех соседей| O(N)| O(deg(v))
Простота реализации| Простая| Требует vector<vector<int>>

При N ≤ 1000 и M ≤ 5000 матрица смежности укладывается в память с большим запасом (1 МБ), а её реализация проще и не требует динамических структур. Поскольку граф не плотный (M ≤ 5000 при N² ≈ 10⁶), список смежности был бы эффективнее по памяти, но:
- Матрица даёт простую итерацию по всем N вершинам без вложенных структур.
- При таких ограничениях разница в скорости незаметна.

2. Статические массивы вместо vector

- Размер известен заранее (N ≤ 1000) — динамическое выделение памяти избыточно.
- Отсутствие накладных расходов vector (указатели, capacity, аллокации).
- Скорость доступа к элементам массива выше или равна vector (в release-сборке — идентична).
- Никаких исключений при аллокации — программа предсказуема.

3. Итеративный DFS вместо рекурсивного· Нет риска переполнения стека вызовов — при N=1000 в худшем случае (цепочка) рекурсия ушла бы на глубину 1000, что близко к лимиту по умолчанию (~1–8 МБ стека).

Ручной стек — простой массив int stack[1001] с указателем top.

4. Почему не BFS?

DFS и BFS для задачи поиска компоненты связности эквивалентны. DFS выбран из-за:
- Простоты стека (не нужна очередь с двумя указателями).
- Отсутствия необходимости в порядке обхода.

---

**Проверка на примере**

Вход:
```
5 4 1
1 2
2 3
3 4
4 5
1
3
```
Разбор: Компьютер 3 отключён. Вирус стартует с 1.
- Заражены: 1 → 2. Из 2 в 3 нельзя (отключён).
- Итого: 2.

Выход: 2
---

# Выводы

- Задача решается обходом графа (DFS/BFS) с фильтрацией отключённых вершин.
- При заданных ограничениях (N ≤ 1000) матрица смежности + статические массивы — оптимальный выбор по простоте и надёжности.
- Итеративный DFS защищает от переполнения стека вызовов.
- Сложность O(N²) по времени и памяти полностью удовлетворяет ограничениям задачи.
