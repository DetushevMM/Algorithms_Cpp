# Хеш-таблица с двойным хешированием

## Описание задачи

Необходимо реализовать хеш-таблицу с открытой адресацией, используя метод разрешения коллизий двойным хешированием.

Хеш-таблица хранит строки и поддерживает три операции:
- "push <строка>" — добавить строку;
- "search <строка>" — проверить наличие строки;
- "pop <строка>" — удалить строку.

При добавлении существующей строки повторная запись не производится.

Для хеширования используется полиномиальная хеш-функция.

---

Формат входных данных
- В первой строке вводится число "N" — количество запросов.
- Далее следуют "N" запросов одного из трёх видов:
```
push <строка>
pop <строка>
search <строка>
```
Например:
```
10
push aiv
push yvbem
search aiv
search woxfyobo
pop guq
pop prhw
pop aiv
push jv
pop aiv
push ubcf
```
---

Формат выходных данных
- Для команд "search" и "pop" необходимо вывести результат: `TRUE`, если операция успешна, и `FALSE`, если нет.

Для команды "push" результат не выводится.

---

## Основная идея алгоритма

В данной реализации используется хеш-таблица размером: `static const int kM = 10007;`

Каждая ячейка таблицы содержит:
```
struct Slot {
    char* str;
    State state;
};
```
где "str" — указатель на хранимую строку, а "state" определяет состояние ячейки.

Используются три состояния:
```
enum State {
    EMPTY,
    OCCUPIED,
    DELETED
};
```
Состояния ячейки

|Состояние| Значение|
|---------|---------|
"EMPTY"| Ячейка никогда не использовалась
"OCCUPIED"| В ячейке находится строка
"DELETED"| Элемент был удалён, но ячейка сохраняется в цепочке пробирования

Последнее состояние особенно важно для корректной работы поиска.

---

## Полиномиальное хеширование

Для получения хеша строки используется полиномиальная функция:
```
h = h * kBase + static_cast<unsigned char>(s[i]);
```
В программе: `static const int kBase = 31;`

Для строки "abc" вычисление выглядит примерно так:
```
h = 0

h = 0 * 31 + 'a'
h = h * 31 + 'b'
h = h * 31 + 'c'
```
В результате получается некоторое большое число.

Затем оно приводится к размеру таблицы: `h % kM`

Первая хеш-функция:
```
unsigned int PolyH1(const char* s) const {
    uint64_t h = 0;

    for (int i = 0; s[i]; ++i) {
        h = h * kBase + static_cast<unsigned char>(s[i]);
    }

    return static_cast<unsigned int>(h % kM);
}
```
Она определяет начальную позицию строки в таблице.

---

Зачем нужны две хеш-функции

Предположим:
```
h1("abc") = 5
h1("xyz") = 5
```
Обе строки хотят попасть в ячейку "5".

Возникает коллизия.

При двойном хешировании используется вторая функция, которая определяет величину шага: `h2(s)`

Позиция "i"-й попытки вычисляется по формуле: `index = (h1(s) + i * h2(s)) % M`, где:
- "h1(s)" — начальная позиция;
- "h2(s)" — шаг;
- "i" — номер попытки;
- "M" — размер таблицы.

---

Вторая хеш-функция

В программе используется: `static const int kQ = 9973;`

Вторая функция:
```
unsigned int StepH2(const char* s) const {
    uint64_t h = 0;

    for (int i = 0; s[i]; ++i) {
        h = h * kBase + static_cast<unsigned char>(s[i]);
    }

    return static_cast<unsigned int>(kQ - (h % kQ));
}
```
Формула: `h2(s) = Q - (h(s) mod Q)`

Так как: `0 <= h mod Q < Q`, то: `1 <= h2 <= Q`

Шаг никогда не равен нулю.

При этом:
```
Q = 9973
M = 10007
```
Оба числа простые, а "Q < M".

Это позволяет получить последовательность пробирования, которая при подходящих параметрах проходит по всей таблице.

---

## Последовательность пробирования

Функция:
```
unsigned int Probe(const char* s, unsigned int i) {
    return (PolyH1(s) + i * StepH2(s)) % kM;
}
```
определяет очередную ячейку.

Например, если:
```
h1(s) = 10
h2(s) = 7
M = 17

получаем:

i = 0: (10 + 0 * 7) % 17 = 10
i = 1: (10 + 1 * 7) % 17 = 0
i = 2: (10 + 2 * 7) % 17 = 7
i = 3: (10 + 3 * 7) % 17 = 14
...
```
То есть после коллизии программа не просто проверяет соседнюю ячейку, а перемещается по собственной последовательности.

Это уменьшает вероятность образования больших кластеров элементов.

---

Почему нельзя просто использовать "EMPTY" после удаления?
Это одна из самых важных особенностей алгоритма.

Предположим, два ключа попали в одну последовательность пробирования:
```
abc → ячейка 5
xyz → ячейка 6
```
После удаления "abc":
```
5 = EMPTY
6 = xyz
```
Теперь выполняется: search xyz

Алгоритм начинает поиск:

ячейка 5 → EMPTY

Если считать "EMPTY" окончанием поиска, программа решит: xyz отсутствует

Хотя "xyz" находится в ячейке "6".

Поэтому после удаления нельзя возвращать ячейку в состояние "EMPTY".

Используется специальное состояние: DELETED

Получается:
```
5 = DELETED
6 = xyz
```
Теперь поиск продолжает пробирование:
```
DELETED → продолжаем
OCCUPIED → проверяем ключ
```
---

Поиск — "Search"

Алгоритм: `bool Search(const char* s)`

Последовательно проверяет ячейки: `i = 0, 1, 2, ..., M-1`

Для каждой попытки вычисляется: `index = (h1(s) + i * h2(s)) % M`

Затем проверяется состояние ячейки. 

"EMPTY"

Если встретилась "EMPTY": ключ отсутствует. Поиск можно завершить.

Почему это корректно?

Если ключ существовал и был помещён в таблицу, то до его позиции в его последовательности пробирования не могло быть "EMPTY". Иначе вставка остановилась бы раньше.

"DELETED"

Если: state == DELETED - поиск продолжается. 

"OCCUPIED"

Если ячейка занята, сравниваем строки: `strcmp(table_[index].str, s) == 0`

При совпадении возвращается: true

---

Вставка — "Push"

Для добавления строки используется: `void Push(const char* s)`

Особенность алгоритма — сохранение первой найденной ячейки "DELETED": `int first_deleted = -1;`

Если встретилась "DELETED":
```
if (first_deleted < 0) {
    first_deleted = index;
}
```
Но поиск не прекращается.

Это необходимо, потому что нужный ключ может находиться дальше.

Например:
```
DELETED
...
OCCUPIED("abc")
```
Если при добавлении ""abc"" сразу использовать "DELETED", получится дубликат.

Поэтому алгоритм:
1. запоминает первую "DELETED";
2. продолжает поиск;
3. проверяет, нет ли уже такого ключа;
4. при встрече "EMPTY" вставляет элемент.

Если ранее была найдена "DELETED", используется именно она:
```
int target =
    (first_deleted >= 0)
        ? first_deleted
        : static_cast<int>(index);
```
Таким образом, удалённые ячейки постепенно переиспользуются.

---

**Защита от дубликатов**

При встрече занятой ячейки: `if (table_[index].state == OCCUPIED)`

сравнивается строка:
```
if (strcmp(table_[index].str, s) == 0) {
    return;
}
```
Если такой ключ уже есть, новая копия не создаётся.

Например:
```
push apple
push apple
```
В таблице остаётся только одна строка: apple

---

Удаление — "Pop"

Метод: `bool Pop(const char* s)` использует ту же последовательность пробирования, что и "Search".

При нахождении нужной строки:
```
delete[] table_[index].str;
table_[index].str = nullptr;
table_[index].state = DELETED;
```
Происходит две операции:

1. освобождается динамическая память;
2. состояние ячейки меняется на "DELETED".

После успешного удаления функция возвращает: true

Если строка не найдена: false

---

## Управление памятью

Строки хранятся в динамической памяти.

При вставке:
```
size_t len = strlen(s);

table_[target].str = new char[len + 1];

memcpy(
    table_[target].str,
    s,
    len + 1
);
```
Для строки: hello выделяется: 6 байт - пять символов плюс завершающий "'\0'".

При удалении используется: `delete[] table_[index].str;`

Деструктор класса освобождает память всех оставшихся строк:
```
~HashTable() {
    for (int i = 0; i < kM; ++i) {
        delete[] table_[i].str;
    }

    delete[] table_;
}
```
Это предотвращает утечки памяти.

## Полный алгоритм работы

Для каждого запроса:
```
push
    ↓
вычислить h1 и h2
    ↓
начать пробирование
    ↓
найти EMPTY или DELETED
    ↓
проверить отсутствие дубликата
    ↓
записать строку

Для "search":

search
    ↓
вычислить h1 и h2
    ↓
пробировать таблицу
    ↓
EMPTY → FALSE
DELETED → продолжить
OCCUPIED + совпадение → TRUE
```
Для "pop":
```
pop
    ↓
вычислить h1 и h2
    ↓
пробировать таблицу
    ↓
EMPTY → FALSE
DELETED → продолжить
OCCUPIED + совпадение
    ↓
delete[]
    ↓
DELETED
    ↓
TRUE
```

## Пример работы

Рассмотрим упрощённую таблицу.

Допустим:
```
h1("cat") = 3
h2("cat") = 5

Тогда последовательность поиска:
i = 0 → 3
i = 1 → 8
i = 2 → 13
i = 3 → 1
...
```
Если ячейка "3" свободна: `3 = cat`

Если затем другой ключ также начинает поиск с "3", возникает коллизия.

Например:
```
dog
h1(dog) = 3
h2(dog) = 4

Тогда "dog" проверит:

3 → 7 → 11 → 15 → ...
```
Если "3" занята, "dog" может попасть в "7".

У двух ключей разные последовательности пробирования.

Тест 3 — проверка "DELETED"

Смысл теста — проверить, что удаление одного элемента не ломает поиск другого элемента, находящегося дальше в той же последовательности пробирования.

Общая схема:
```
push A

pop A

```
После удаления "A" его ячейка должна иметь состояние: DELETED, а не: EMPTY

Поэтому поиск "B" продолжает пробирование и находит элемент.

## Сложность

Пусть:
```
M = размер таблицы
α = n / M

где "α" — коэффициент заполнения.
```
|Операция| Средний случай| Худший случай|
|--------|---------------|--------------|
"push"| O(1)| O(M)
"search"| O(1)| O(M)
"pop"| O(1)| O(M)

В среднем при небольшом коэффициенте заполнения операции выполняются за константное время.

При приближении: `α → 1`

количество проб резко увеличивается.

Поэтому открытая адресация обычно используется при неполной заполненности таблицы.

Для данной реализации разумно поддерживать: `α < 0.7`

---

**Использование памяти**

Таблица содержит: M = 10007 ячеек.

Каждая ячейка содержит:
```
char* str;
State state;
```
Кроме того, для каждой сохранённой строки отдельно выделяется память под её символы.

Дополнительная память алгоритма поиска и хеширования — "O(1)".

Общая память: `O(M + S)`, где "S" — суммарная длина хранимых строк.

---

Сравнение с методом цепочек

|Характеристика| Цепочки| Двойное хеширование|
|--------------|--------|--------------------|
Основное хранилище| массив списков/узлов| массив ячеек
Дополнительные указатели| обычно есть| нет
Локальность памяти| хуже| лучше
Удаление| простое| требует "DELETED"
Кластеризация| зависит от реализации| значительно меньше, чем при линейном пробировании
Заполнение до 100%| возможно| нежелательно
Необходимость "DELETED"| нет| да

Главное преимущество двойного хеширования — элементы хранятся непосредственно в массиве, поэтому структура хорошо использует локальность памяти.

Главный недостаток — необходимость аккуратно обрабатывать удаление и следить за коэффициентом заполнения.

---

**Важные особенности реализации**

1. Таблица фиксированного размера `static const int kM = 10007;` Размер таблицы не изменяется во время работы программы.

2. Использование "uint64_t"

При вычислении полиномиального хеша: `uint64_t h = 0;` используется 64-битное беззнаковое число.

Это позволяет значительно уменьшить риск переполнения во время промежуточных вычислений.

В конце хеш приводится к размеру таблицы: `h % kM`

3. Одинаковая последовательность пробирования

Для конкретной строки значения:
```
h1(s)
h2(s)
```
всегда одинаковы.

Поэтому "push", "search" и "pop" используют одну и ту же последовательность ячеек. Это необходимо для корректности структуры.

4. "EMPTY" и "DELETED" — разные состояния

Это принципиально важно:
```
EMPTY   → поиск можно завершить
DELETED → поиск продолжается
OCCUPIED → проверяем ключ
```
Если перепутать "EMPTY" и "DELETED", поиск после удаления может стать некорректным.

## Итог

В программе реализована хеш-таблица с открытой адресацией и двойным хешированием.

Основная формула пробирования: `index(i) = (h1(s) + i · h2(s)) mod M`

Используются две полиномиальные хеш-функции:
```
h1(s) → начальная позиция
h2(s) → шаг пробирования
```
Для корректного удаления используются три состояния:
```
EMPTY
OCCUPIED
DELETED

Основные операции:
Push   — добавление
Search — поиск
Pop    — удаление
```
Средняя сложность каждой операции составляет O(1) при умеренной заполненности таблицы, а худшая — O(M).

Ключевой принцип реализации:

«Удалённая ячейка не становится "EMPTY": она становится "DELETED", чтобы не нарушить цепочку пробирования.»
