# Сортировка вставками (Insertion Sort)

1. Задача

Реализовать сортировку вставками по неубыванию.

Неубывающий порядок означает: `a[0] <= a[1] <= a[2] <= ... <= a[n-1]`

2. Идея алгоритма

Сортировка вставками работает примерно так же, как человек сортирует карты в руке.

Массив постепенно разделяется на две части:
```
[ отсортированная часть ][ ещё не обработанные элементы ]
             ↑
          граница
```
На каждой итерации берём один элемент из правой части и вставляем его в правильное место отсортированной левой части.

Например:
```
[2, 5, 8, 12 | 6, 10, 15]
              ↑
          current = 6
```
Нужно вставить "6" между "5" и "8": `[2, 5, 6, 8, 12 | 10, 15]`

После этого первые элементы снова отсортированы.

---

3. Основной алгоритм

```
void InsertionSort(int arr[], int n) {
  for (int i = 1; i < n; ++i) {
    int current = arr[i];

    int j = 0;

    for (j = i - 1; j >= 0 && arr[j] > current; --j) {
      arr[j + 1] = arr[j];
    }

    arr[j + 1] = current;
  }
}
```
Почему начинаем с "i = 1"?

Элемент с индексом "0" уже можно считать отсортированной частью из одного элемента:
```
[5 | 2, 4, 6, 1, 3]
 ↑
отсортировано
```
Поэтому первый элемент обрабатывать не нужно.

Начинаем со второго: i = 1

---

4. Что происходит внутри цикла

Главные строки:
```
int current = arr[i];
for (j = i - 1; j >= 0 && arr[j] > current; --j) {
  arr[j + 1] = arr[j];
}
arr[j + 1] = current;
```
Шаг 1. Запоминаем элемент: `int current = arr[i];`

Например:
```
[2, 5, 4, 6, 1, 3]
       ↑
   current = 4
```
Мы временно сохраняем "4", потому что следующие элементы будут сдвигаться вправо.

---

Шаг 2. Идём влево
```
j = i - 1;

Для "i = 2":

[2, 5, 4, 6, 1, 3]
    ↑  ↑
    j  current
```
Сравниваем:
```
arr[j] > current
5 > 4
```
Условие истинно, поэтому "5" нужно сдвинуть вправо: `arr[j + 1] = arr[j];`

Получаем: `[2, 5, 5, 6, 1, 3]`

Затем: `--j;` - "j" перемещается ещё левее.

---

Шаг 3. Проверяем следующий элемент

Теперь:
```
[2, 5, 5, 6, 1, 3]
 ↑
 j
```
Сравниваем: 2 > 4?

Условие ложно. Значит, дальше двигаться не нужно.

---

Шаг 4. Вставляем "current"

Сейчас "j" указывает на элемент, который меньше либо равен "current". Поэтому "current" нужно поставить на следующую позицию:

arr[j + 1] = current;

Получаем: `[2, 4, 5, 6, 1, 3]`

Левая часть снова отсортирована.

---

5. Почему элементы сдвигаются, а не меняются местами

Можно было бы использовать множество обменов:
```
[2, 5, 4]
       ↓
[2, 4, 5]
```
Но сортировка вставками работает иначе.

Сначала освобождается место: [2, 5, 5], а затем туда помещается "4": [2, 4, 5]

Это особенно удобно, когда один элемент необходимо переместить далеко влево.

---

6. Пошаговый пример

Исходный массив:
```
[5, 2, 4, 6, 1, 3]
"i = 1"
current = 2
```
Сравниваем с "5": `5 > 2?`

Сдвигаем "5": [5, 5, 4, 6, 1, 3]

Вставляем "2": [2, 5, 4, 6, 1, 3]

Отсортированная часть: [2, 5]

---
```
"i = 2"
current = 4
```
Сравниваем с "5": `5 > `4?

Сдвигаем: [2, 5, 5, 6, 1, 3]

Сравниваем с "2": `2 > 4  → false`

Вставляем "4": [2, 4, 5, 6, 1, 3]

Отсортированная часть: [2, 4, 5]

---
```
"i = 3"
current = 6
"5 > 6" — нет.
```
Ничего сдвигать не нужно: [2, 4, 5, 6, 1, 3]

---
```
"i = 4"
current = 1
```
Сдвигаем все элементы, которые больше "1":
```
[2, 4, 5, 6, 6, 3]
[2, 4, 5, 5, 6, 3]
[2, 4, 4, 5, 6, 3]
[2, 2, 4, 5, 6, 3]
```
Вставляем "1": [1, 2, 4, 5, 6, 3]

---
```
"i = 5"
current = 3
```
Сдвигаем:
```
[1, 2, 4, 5, 5, 6]
[1, 2, 4, 4, 5, 6]
```
Вставляем "3": [1, 2, 3, 4, 5, 6]

Массив отсортирован.

---

7. Важное условие "arr[j] > current"

Внутренний цикл содержит: `arr[j] > current`, а не: `arr[j] >= current`

Это означает, что элементы, равные "current", не перемещаются друг относительно друга. Поэтому данная реализация является стабильной сортировкой.

Например: [3a, 2, 3b] после сортировки: [2, 3a, 3b] - Порядок одинаковых элементов сохраняется.

10. Сложность

|Случай| Сложность|
|------|----------|
Лучший случай — массив уже отсортирован| "O(n)"
Средний случай| "O(n²)"
Худший случай — обратный порядок| "O(n²)"
Дополнительная память| "O(1)"

Почему лучший случай "O(n)"?

Если массив уже отсортирован: [1, 2, 3, 4, 5], то для каждого "current" проверка: arr[j] > current сразу оказывается ложной. Сдвигов элементов не происходит.

Почему худший случай "O(n²)"?

Если массив расположен в обратном порядке: [5, 4, 3, 2, 1], каждый новый элемент приходится сравнивать и сдвигать почти через всю уже отсортированную часть.

---

11. Основные свойства

Сортировка вставками в данной реализации:

- сортирует по неубыванию;
- работает непосредственно в исходном массиве;
- не требует дополнительного массива;
- имеет сложность "O(n²)" в среднем и худшем случае;
- имеет сложность "O(n)" для уже отсортированного массива;
- является стабильной;
- хорошо подходит для небольших массивов и данных, которые уже частично отсортированы.

Главное, что нужно запомнить

1. Левая часть массива всегда отсортирована.
2. Берём следующий элемент → current.
3. Идём слева направо по элементам, а внутри текущей итерации — справа налево.
4. Все элементы больше current сдвигаем вправо.
5. current вставляем в освободившееся место.

Именно операция «сдвинуть большие элементы → вставить current» является основной идеей Insertion Sort.
