# Путь по лабиринту

## Условие задачи

Дан прямоугольный лабиринт размера N × M. Каждая клетка обозначена одним из символов:
```
· . — свободная клетка;
· # — стена;
· S — стартовая клетка (ровно одна);
· F — финишная клетка (ровно одна).
```
За один шаг разрешено перейти из текущей свободной клетки в соседнюю по стороне (вверх, вниз, влево, вправо), если она не является стеной. Необходимо найти минимальное количество шагов от S до F.

Формат ввода:
- Первая строка: два целых числа N и M — количество строк и столбцов.
- Следующие N строк: по M символов каждая — описание лабиринта.

Формат вывода:
- Одно целое число — минимальное число шагов от S до F.
- Если добраться невозможно — вывести -1.

Ограничения
```
· 1 ≤ N, M ≤ 1000
· N · M ≤ 2 · 10^5
```
Примеры

Пример 1
```
Ввод:          Вывод:
3 5            5
S...#
.##.#
...F#
```
Пример 2
```
Ввод:          Вывод:
4 4            6
S###
...#
##.#
##.F
```
Пример 3
```
Ввод:          Вывод:
3 3            -1
S##
###
##F
```
---

## Идея решения

Задача сводится к поиску кратчайшего пути в невзвешенном графе, где:
- вершины — свободные клетки лабиринта (S, F, .);
- рёбра — переходы между соседними по стороне свободными клетками;
- вес каждого ребра равен 1 (один шаг).

Для невзвешенных графов классическим и оптимальным инструментом является поиск в ширину (BFS). Он исследует граф «волнами»: сначала все клетки на расстоянии 1 от старта, затем на расстоянии 2, и так далее. Благодаря этому первое достижение финишной клетки гарантированно соответствует кратчайшему пути.

---

## Алгоритм

1. Чтение и подготовка. Считываем лабиринт в виде двумерного массива символов. Попутно находим координаты стартовой клетки S.
2. Инициализация. Создаём массив расстояний dist[N][M], изначально заполненный значением -1 (клетка не посещена). Для старта dist = 0.
3. Очередь. Помещаем стартовую клетку в очередь. Очередь реализуется через std::vector с указателем на «голову» — это избавляет от необходимости удалять элементы из начала и использовать std::queue.
4. Основной цикл BFS. Пока очередь не пуста:
   - Извлекаем текущую клетку.
   - Если это финиш F — выводим её расстояние и завершаем работу.
   - Для каждого из четырёх соседей проверяем:
     - не выходит ли за границы поля;
     - не является ли стеной #;
     - не была ли уже посещена (dist != -1).
   - Если все проверки пройдены, записываем dist[сосед] = dist[текущая] + 1 и добавляем соседа в очередь.
5. Завершение. Если очередь опустела, а финиш не найден — путь недостижим, выводим -1.

Почему проверка на F выполняется при извлечении, а не при добавлении

Формально BFS можно завершать и в момент добавления финиша в очередь — расстояние в этот момент уже минимально. Однако проверка при извлечении делает код единообразным и наглядно демонстрирует инвариант BFS: к моменту, когда вершина извлекается из очереди, её расстояние окончательно и минимально.

## Выбор решения

BFS выбран по следующим причинам:
- Корректность. В невзвешенном графе BFS всегда находит кратчайший путь — это его фундаментальное свойство.
- Оптимальность по времени. Алгоритм обрабатывает каждую вершину и каждое ребро ровно один раз.
- Простота реализации. Не требуется сложных структур данных, достаточно очереди и массива расстояний.
- Альтернативы хуже подходят:
  - DFS не гарантирует кратчайший путь в общем случае.
  - Алгоритм Дейкстры избыточен — все рёбра имеют единичный вес.
  - A* требует эвристики и не даёт выигрыша при равномерной сетке.

**Особенности реализации**
- Используется минимальный набор библиотек (<iostream>, <vector>), без <algorithm> и <queue>.
- Очередь моделируется вектором с индексом head — это даёт компактный код и хорошую производительность.
- Память под очередь резервируется заранее (reserve(N · M)), чтобы избежать реаллокаций.
- Обход соседей выполняется через два статических массива смещений dx/dy, что устраняет дублирование кода.

## Оценка сложности

Пусть V = N · M — количество клеток, E ≤ 4V — количество рёбер.

|Параметр| Оценка| Пояснение|
|--------|-------|----------|
Время| O(N · M)| Каждая клетка добавляется в очередь не более одного раза, для каждой проверяются 4 соседа — итого O(4 · N · M) операций.
Память| O(N · M)| Хранение массива расстояний и очереди.

С учётом ограничения N · M ≤ 2 · 10^5 решение укладывается в лимиты с большим запасом (порядка 10^6 операций).

### Проверка на примерах

1. Пример 1. Путь: `(0,0) → (0,1) → (0,2) → (0,3) → (1,3) → (2,3)`. Длина — 5. ✔
2. Пример 2. Единственный путь огибает стену слева вниз, затем вправо и вниз. Длина — 6. ✔
3. Пример 3. Финиш F полностью изолирован стеной — очередь опустеет, не дойдя до него. Ответ -1. ✔

## Итог

Решение представляет собой классический BFS на сетке. Оно сочетает простоту, оптимальную асимптотику и минимальные зависимости, что делает его удобным как для олимпиадных задач, так и для учебных целей.
