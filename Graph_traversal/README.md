# Обход графа в глубину (DFS)

Два варианта решения задачи об обходе неориентированного графа в глубину.

---

## Условие задачи

Дан неориентированный граф и стартовая вершина S.

Необходимо выполнить обход графа в глубину (DFS), начиная с вершины S, и вывести вершины в порядке их первого посещения.

Дополнительные требования:
- Если из текущей вершины можно перейти в несколько ещё не посещённых вершин, сначала переходим в вершину с меньшим номером.
- Выводим только вершины, достижимые из S.

Формат ввода
```
N M S
u₁ v₁
u₂ v₂
...
u_M v_M
· N — количество вершин (1 ≤ N ≤ 1000)
· M — количество рёбер (0 ≤ M ≤ 5000)
· S — стартовая вершина (1 ≤ S ≤ N)
· Каждая из следующих M строк содержит пару u, v — концы ребра.
· Граф неориентированный, без петель и кратных рёбер.
```
Формат вывода
- Номера вершин в порядке их первого посещения алгоритмом DFS, начиная с S. Разделитель — пробел.

Пример

Вход:
```
5 5 1
1 3
1 2
2 4
3 4
4 5
```
Выход: `1 2 4 3 5`

---

## Общая идея

DFS (Depth-First Search, поиск в глубину) — алгоритм обхода графа, при котором мы идём «вглубь» настолько, насколько возможно, и только потом возвращаемся и пробуем другие ветви.

Ключевые моменты:
1. Стек (явный или неявный через рекурсию) хранит вершины, которые ещё предстоит обработать.
2. Массив посещённых visited[] предотвращает повторный заход в уже обработанные вершины.
3. Порядок обхода соседей — по возрастанию номера, что даёт детерминированный результат и удовлетворяет условию задачи.

При первом извлечении вершины из стека мы её «посещаем»: помечаем visited[v] = true и добавляем в результирующий порядок.

---

## Представление графа

Для обеих реализаций используется матрица смежности adj[u][v] размера (N+1) × (N+1):
- adj[u][v] = true, если между u и v есть ребро.
- Первая строка и первый столбец не используются — индексация вершин с 1.

Почему матрица, а не списки смежности?
- Удобный перебор соседей по возрастанию номера. Достаточно пройти циклом u от 1 до N — порядок соблюдается автоматически. Со списками пришлось бы сортировать соседей.
- Простота реализации без STL-контейнеров.
- Ограничения по N (N ≤ 1000) позволяют держать матрицу: 1000 × 1000 — около 1 МБ (или ~125 КБ при std::vector<bool>). Это приемлемо.

При больших N (десятки тысяч и больше) матрица стала бы неэффективной по памяти — тогда нужны списки смежности с предварительной сортировкой.

# Вариант 1. Итеративный DFS (со стеком на массиве/векторе)

## Идея

Явно используем стек. Кладём в него стартовую вершину, затем в цикле:
1. Извлекаем вершину с вершины стека.
2. Если она уже посещена — пропускаем (могла быть положена несколько раз).
3. Иначе помечаем как посещённую и добавляем в результат.
4. Кладём в стек всех непосещённых соседей в порядке убывания номеров.

**Ключевой трюк с порядком**

Стек работает по принципу LIFO: последним положили — первым достали. Чтобы из стека первым извлекался сосед с наименьшим номером, кладём их в порядке убывания номеров.

Например, если у вершины v соседи {2, 3, 5}, то в стек идут 5, 3, 2, а извлекаются — 2, 3, 5. Это ровно то, что требует условие.

**Структуры данных**

|Что| Как| Размер|
|---|----|-------|
Матрица смежности| std::vector<std::vector<bool>>| (N+1)×(N+1)
Стек| std::vector<int> (push_back / pop_back / back)| до N
Посещённые| std::vector<bool>| N+1
Результат| std::vector<int>| до N

Сложность:
- Время: O(N²) — из-за перебора всех N возможных соседей для каждой посещённой вершины (матрица смежности).
- Память: O(N²) на матрицу + O(N) на служебные массивы.

Плюсы:
- Нет риска переполнения стека вызовов при большой глубине рекурсии.
- Прозрачное управление состоянием (стек видно явно).
- Легко добавить дополнительную логику (например, отладочный вывод содержимого стека).

Минусы:
- Код длиннее и менее «декларативный», чем рекурсивный вариант.
- Нужно не забыть проверку if (visited[v]) continue; — без неё вершины могут дублироваться в выводе.

# Вариант 2. Рекурсивный DFS

## Идея

Функция dfs(v):1. Помечает v как посещённую.
2. Выводит (или сохраняет) v.
3. Перебирает соседей u от 1 до N — при этом порядок по возрастанию номера соблюдается автоматически.
4. Для каждого непосещённого соседа u рекурсивно вызывает dfs(u).

**Почему перебор «от 1 до N» даёт правильный порядок?**

Условие задачи: сначала идём в наименьшего непосещённого соседа. Перебор u по возрастанию и рекурсивный вызов сразу при нахождении подходящего соседа — ровно это и делает. Никакой дополнительной сортировки не нужно.

Стек вызовов:
- Рекурсия использует стек вызовов языка — по сути тот же самый LIFO, но управляемый рантаймом. Глубина рекурсии не превышает количества посещённых вершин, то есть ≤ N.
- При N ≤ 1000 глубина ≤ 1000 — это безопасно почти на любой платформе (стандартный размер стека потока обычно 1–8 МБ, одной вершине соответствует один небольшой кадр).

Сложность:
- Время: O(N²) — та же причина (матрица смежности).
- Память: O(N²) на матрицу + O(N) на стек вызовов и массивы.

Плюсы:
- Код короткий и почти дословно повторяет математическое определение DFS.
- Не нужно думать о порядке укладывания в стек — порядок обеспечивается перебором u по возрастанию.
- Меньше шансов ошибиться с дубликатами вершин: каждая вершина обрабатывается строго один раз.

Минусы:
- При очень больших N возможен stack overflow.
- Сложнее отлаживать при нетривиальной логике (неявный стек).

---

## Сравнение

|Критерий| Итеративный (стек)| Рекурсивный|
|--------|-------------------|------------|
Длина кода| Больше| Меньше
Читаемость| Средняя| Высокая
Соответствие условию «меньший сосед первым»| Через порядок укладывания в стек (убывание)| Автоматически через перебор по возрастанию
Риск stack overflow| Нет| Есть при больших N
Сложность| O(N²) по времени| O(N²) по времени
Управление памятью стека| Явное| Неявное (рантайм)

---

### Почему используется std::vector

1. Динамический размер. Матрицу смежности и массивы можно создавать ровно под N+1 элементов — не нужны константы вида MAX_N и запас «на всякий случай». При разных тестах с разными N не приходится перекомпилировать.
2. Автоматическое управление памятью. Не нужно вручную писать new[]/delete[] или рисковать утечкой при раннем return. RAII избавляет от целого класса ошибок.
3. std::vector<bool> экономит память. Хранит по 1 биту на элемент вместо 1 байта — для матрицы 1000×1000 это ~125 КБ вместо ~1 МБ.
4. Стек остаётся стеком. push_back / pop_back / back — это те же операции LIFO, только без ручной работы с индексом stackSize. Логика алгоритма от этого не меняется.
5. Алгоритмическая суть сохраняется. vector — это контейнер, а не алгоритм. Использование вектора вместо сырого массива — деталь реализации, а не «магия STL», подменяющая саму идею DFS.

Оба варианта дают одинаковый корректный ответ и одинаковую асимптотику O(N²), различаясь лишь способом организации стека и стилем кода.
