# Кратчайший путь в неориентированном невзвешенном графе

## Условие задачи

Дан неориентированный невзвешенный граф и две вершины S и T. Требуется найти любой кратчайший путь из S в T.
Длина пути — это количество рёбер в нём.

Формат ввода:
- В первой строке записаны четыре целых числа N, M, S, T — количество вершин, количество рёбер, стартовая и конечная вершины.
- В следующих M строках записаны по два целых числа u и v — концы неориентированного ребра.

Ограничения:
```
· 1 ≤ N ≤ 10^5
· 0 ≤ M ≤ 2·10^5
· 1 ≤ S, T ≤ N
· Петель нет
```
Формат вывода:
- Если пути из S в T нет, выведите -1.
- Иначе в первой строке выведите длину кратчайшего пути L, а во второй строке — L+1 номер вершины в порядке прохождения пути. Если кратчайших путей несколько, разрешается вывести любой из них.

Примеры

Пример 1
```
Ввод:              Вывод:
6 6 1 6            3
1 2                1 2 3 6
2 3
3 6
1 4
4 5
5 6
```
Пример 2
```
Ввод:              Вывод:
5 2 1 5            -1
1 2
4 5
```
Пример 3
```
Ввод:              Вывод:
4 4 2 2            0
1 2                2
2 3
3 4
4 1
```
---

## Идея решения

Задача классическая: поиск кратчайшего пути в невзвешенном графе. Ключевое наблюдение — раз все рёбра имеют одинаковый вес (1), можно применить поиск в ширину (BFS).

BFS обходит граф «волнами»: сначала все вершины на расстоянии 1 от старта, затем на расстоянии 2, и так далее. Это гарантирует, что при первом попадании в вершину мы нашли кратчайшее расстояние до неё.

Почему не Дейкстра или DFS?
- Дейкстра избыточен: он нужен для графов с произвольными неотрицательными весами. При единичных весах BFS работает проще и быстрее (без приоритетной очереди).
- DFS в принципе не годится: он находит какой-то путь, но не обязательно кратчайший, и может уйти в глубокую ветку, обойдя короткий маршрут.

---

## Алгоритм

Шаг 1. Построение графа:
 - Граф хранится в виде списка смежности: для каждой вершины — вектор соседей. Такой формат даёт суммарную память O(N + M) и позволяет перебирать соседей за время, пропорциональное их числу. Матрица смежности не подходит: при N = 10^5 она заняла бы порядка 10^10 ячеек.

Шаг 2. BFS от стартовой вершины:
 - Заводим два массива:
  - dist[v] — кратчайшее расстояние от S до v (инициализируется -1 = «не посещено»);
  - parent[v] — предок v в дереве обхода (нужен для восстановления пути).

Стартовую вершину помечаем dist[S] = 0 и кладём в очередь. Далее, пока очередь не пуста:
1. Извлекаем вершину v.
2. Для каждого соседа to: если он ещё не посещён (dist[to] == -1), записываем dist[to] = dist[v] + 1, parent[to] = v и добавляем to в очередь.

Проверка dist[to] == -1 одновременно служит и отметкой о посещении, и защитой от повторного попадания в очередь — это важно для корректности и линейного времени.

Шаг 3. Проверка достижимости:
- Если после BFS dist[T] == -1, вершина T в одной компоненте связности с S не находится — выводим -1.

Шаг 4. Восстановление пути:
- Идём от T по ссылкам parent вплоть до S, собирая вершины в вектор. Полученная последовательность идёт в обратном порядке — её нужно развернуть (или вывести в обратном порядке). Длина пути равна dist[T], количество вершин в выводе — dist[T] + 1.

---

## Оценка сложности

|Ресурс| Оценка| Пояснение|
|------|-------|----------|
Время| O(N + M)| Каждая вершина попадает в очередь не более одного раза, каждое ребро просматривается из обоих концов
Память| O(N + M)| Список смежности + массивы dist, parent, очередь

При максимальных ограничениях (N = 10^5, M = 2·10^5) это порядка 3·10^5 операций — укладывается в любой разумный лимит времени с большим запасом.

---

**Граничные случаи**
- S == T — расстояние равно 0, путь состоит из одной вершины. BFS обрабатывает это естественно, без специальных проверок (см. пример 3).
- `M == 0` — граф без рёбер; при `S != T` ответ -1.
- Несвязный граф — недостижимые вершины остаются с dist = -1, что сразу даёт ответ -1.
- Несколько кратчайших путей — BFS найдёт любой из них; в условии разрешено выводить любой.

---

Реализационные заметки· Используется список смежности на vector<vector<int>> — оптимально по памяти и скорости.
- Массивы размера N + 1 для удобной индексации с единицы (вершины нумеруются от 1).
- Восстановление пути через массив parent — стандартный приём, позволяющий не хранить весь путь в процессе обхода.
- Условие задачи требует минимальный набор библиотек и запрещает <algorithm>, поэтому:
  - разворот пути выполняется вручную (циклом с конца к началу),
  - поиск минимума/сортировка не требуются — BFS сам гарантирует кратчайшие расстояния.

---

## Итог

Выбранный подход — BFS на списке смежности с восстановлением пути по массиву предков — является каноническим решением задачи о кратчайшем пути в невзвешенном графе. Он оптимален по времени и памяти, прост в реализации и корректно обрабатывает все граничные случаи.
