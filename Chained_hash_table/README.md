## Хеш-таблица с методом цепочек

# Описание задачи

Необходимо реализовать хеш-таблицу для хранения строк с разрешением коллизий методом цепочек.

Поддерживаются операции:
- "push <строка>" — добавить строку;
- "pop <строка>" — удалить строку;
- "search <строка>" — проверить наличие строки.

Для хеширования используется полиномиальная хеш-функция.

В реализации не используются контейнеры STL: строки хранятся через "char*", а цепочки реализованы вручную с помощью односвязных списков.

---

Формат ввода:
- В первой строке вводится количество запросов "N".
- Затем идут "N" команд:
```
push aiv
push yvbem
search aiv
pop aiv
```
---

Формат вывода
- Для "search":
```
- "TRUE" — строка найдена;
- "FALSE" — строка отсутствует.
```
- Для "pop":
```
- "TRUE" — строка была найдена и удалена;
- "FALSE" — строка отсутствует.
```
- Команда "push" ничего не выводит.

---

*Устройство хеш-таблицы*

Основная структура:
```
Строка
   ↓
хеш-функция
   ↓
индекс
   ↓
table[index]
   ↓
цепочка Node → Node → Node
```
Массив "table" содержит указатели на начало цепочек:
- Node** table;
- Каждый элемент цепочки имеет:
```
struct Node {
    char* str;
    Node* next;
};
```
То есть "Node" хранит строку и указатель на следующий элемент.

---

**Полиномиальное хеширование**

Хеш вычисляется следующим образом:
```
size_t h = 0;

for (int i = 0; str[i] != '\0'; ++i) {
    h = h * BASE + (unsigned char)str[i];
}

return h % kTableSize;
```
**В программе используются:**
```
BASE = 31
kTableSize = 10007
```
Для каждого символа: `h = h × 31 + код_символа`

После обработки всей строки получается большое число. Оператор "%" преобразует его в допустимый индекс массива: `h % kTableSize`

Например, если результат хеширования равен "96354": `96354 % 10007 = 633`

Значит, строка будет искатьcя в: `table[633]` 

Зачем нужен "%"

Размер таблицы — "10007", поэтому допустимые индексы: 0 ... 10006. Остаток от деления гарантирует попадание в этот диапазон.

# Коллизии

Разные строки могут получить одинаковый индекс:
```
hash("abc") → 500
hash("xyz") → 500
```
Это называется коллизией.

Для её разрешения используется цепочка:
```
table[500]
    ↓
"abc" → "xyz" → "hello" → nullptr
```
Поэтому элементы с одинаковым хеш-индексом хранятся в одном односвязном списке.

Важно: одинаковый хеш ещё не означает одинаковые строки. После попадания в цепочку выполняется точное сравнение через: `strcmp(current->str, str)`

---

"push" — добавление

Алгоритм:

1. Вычислить хеш строки.
2. Получить индекс таблицы.
3. Пройти соответствующую цепочку.
4. Если такая строка уже существует — ничего не делать.
5. Иначе создать новый "Node".
6. Добавить его в начало цепочки.

## Основная часть:
```
size_t index = PolyHash(str);

Node* current = table[index];

while (current != nullptr) {
    if (std::strcmp(current->str, str) == 0) {
        return;
    }
    current = current->next;
}

Node* newNode = new Node(str);
newNode->next = table[index];
table[index] = newNode;
```
Новый элемент вставляется в начало списка:

Было: `table[500] → cat → dog → nullptr`

Добавляем hello:
```
newNode → hello
             ↓
            cat → dog
```
После: `table[500] → hello → cat → dog → nullptr`

---

**"search" — поиск**

Сначала вычисляется хеш и определяется нужная цепочка.

Например:
```
"hello"
   ↓
hash
   ↓
500
   ↓
table[500]
```
Затем цепочка последовательно проверяется:
```
while (current != nullptr) {
    if (std::strcmp(current->str, str) == 0) {
        return true;
    }

    current = current->next;
}
```
Если строка найдена — "TRUE".

Если достигнут "nullptr" — "FALSE".

---

**"pop" — удаление**

Для удаления также сначала определяется нужная цепочка.

При обходе используются два указателя:
```
Node* current = table[index];
Node* prev = nullptr;
```
Например: `table[500]`
```
hello → cat → dog → nullptr
         ↑
       current
```
Если найден "cat", нужно исключить его из списка:
```
hello → cat → dog
         ↓
      удаляем

hello ─────────→ dog
```
Для этого:
```
prev->next = current->next;
delete current;
```
Удаление первого элемента. Если удаляется первый элемент цепочки, "prev == nullptr".

Тогда изменяется указатель таблицы: `table[index] = current->next;`

Например:

Было: `table[500] → hello → cat → dog`

После удаления hello: `table[500] → cat → dog`

При успешном удалении возвращается "TRUE", иначе "FALSE".

---

**Хранение строк и память**

Так как "std::string" не используется, каждая строка копируется вручную.

В конструкторе "Node":
```
size_t len = strlen(s);

str = new char[len + 1];

std::memcpy(str, s, len);

str[len] = '\0';
```
Получается независимая копия строки.

При уничтожении "Node" память освобождается:
```
~Node() {
    delete[] str;
}
```
Таким образом, каждый созданный "Node" владеет собственной строкой.

---

**Деструктор хеш-таблицы**

Таблица и все её узлы создаются динамически, поэтому их необходимо освободить.

Деструктор проходит по всем ячейкам:
```
for (int i = 0; i < kTableSize; ++i)
```
и удаляет каждый элемент соответствующей цепочки:
```
while (current != nullptr) {
    Node* to_delete = current;
    current = current->next;
    delete to_delete;
}
```
После удаления всех цепочек освобождается сам массив: `delete[] table;`

Сначала сохраняется "current->next", и только после этого удаляется текущий узел. Иначе после "delete" нельзя было бы безопасно обратиться к его "next".

---

Пример работы

Для команд:
```
push aiv
push yvbem
search aiv
search woxfyobo
pop guq
pop aiv
```
можно представить структуру следующим образом:
```
push aiv

table[hash(aiv)]
        ↓
       aiv
```
После "push yvbem" появляется ещё одна цепочка или элемент в существующей цепочке — в зависимости от хешей.

Команда: `search aiv` вычисляет хеш "aiv", переходит в соответствующую ячейку и сравнивает строки. Результат: `TRUE`

Если "woxfyobo" в таблице отсутствует: `search woxfyobo` - результат: `FALSE`

При: `pop aiv` узел удаляется из соответствующей цепочки, поэтому результат: `TRUE`

# Сложность

Пусть:

- "N" — количество элементов;
- "L" — длина строки;
- "α = N / kTableSize" — средняя длина цепочки.

Вычисление хеша требует пройти по всей строке: `O(L)`

При хорошем распределении элементов:

|Операция| Средняя сложность| Худший случай|
|--------|------------------|--------------|
Хеширование| "O(L)"| "O(L)"
"push"| "O(L)"| "O(N × L)"
"search"| "O(L)"| "O(N × L)"
"pop"| "O(L)"| "O(N × L)"

Дополнительная память: `O(N × L)`

для хранения самих строк и узлов.

Худший случай возникает, если большое количество строк попадает в одну цепочку. Тогда хеш-таблица фактически превращается в односвязный список.

---

# Основная идея алгоритма

Вся работа хеш-таблицы сводится к следующей последовательности:
```
СТРОКА
   ↓
ПОЛИНОМИАЛЬНЫЙ ХЕШ
   ↓
ИНДЕКС ТАБЛИЦЫ
   ↓
ЦЕПОЧКА
   ↓
strcmp()
   ↓
НАЙДЕНА / НЕ НАЙДЕНА
```
Хеш-функция быстро определяет, где искать, а цепочка и "strcmp()" позволяют точно определить, есть ли нужная строка.

Метод цепочек позволяет хранить несколько элементов с одинаковым хеш-индексом, не теряя их при возникновении коллизий.
