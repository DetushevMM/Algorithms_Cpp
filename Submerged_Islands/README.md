# Затопленные острова

## Условие задачи

После сильного дождя местность представлена прямоугольной картой.

Символ # обозначает сушу, а символ '.' — воду. Две клетки суши относятся к одному острову, если из одной можно попасть в другую, переходя только между клетками с общей стороной: вверх, вниз, влево или вправо.

Определите количество островов.

Формат ввода:
- В первой строке записаны два целых числа N и M — количество строк и столбцов карты.
- В следующих N строках записано по M символов # или ..
- Ограничения: 1 ≤ N, M ≤ 100.

Формат вывода:
- Выведите одно целое число — количество островов.

Пример

Ввод:
```
3 4
.##.
####
..#.
```
Вывод: 1
- Пояснение: все клетки суши связаны между собой по сторонам, образуя один остров.

---

## Идея решения

Задача сводится к классическому поиску количества компонент связности в графе, где:
- Вершины — клетки суши (#).
- Рёбра — связь между двумя клетками суши, имеющими общую сторону.

Каждая компонента связности — это один остров. Значит, нужно посчитать число таких компонент.

Для этого используется обход в глубину (DFS), который «затапливает» найденный остров: после посещения клетки она помечается как вода (.), чтобы больше не рассматриваться. Так мы гарантированно обрабатываем каждую клетку ровно один раз.

---

## Алгоритм

1. Чтение карты. Считываем N строк по M символов в vector<string>.
2. Перебор всех клеток. Проходим по карте слева направо, сверху вниз.
3. Обнаружение нового острова. Если текущая клетка равна #:
   - Увеличиваем счётчик островов.
   - Запускаем обход (DFS) от этой клетки, чтобы «затопить» весь остров.
4. Обход в глубину (итеративный, со стеком).
   - Помещаем стартовую клетку в стек и сразу заменяем её на ..
   - Пока стек не пуст:
     - Извлекаем клетку из стека.
     - Для каждого из четырёх соседей (вверх, вниз, влево, вправо):
       - Если сосед в границах карты и равен #:
         - Помечаем его как . (посещён).
         - Кладём в стек.
   - Важно: помечать клетку как посещённую в момент добавления в стек, а не в момент извлечения — иначе одну и ту же клетку можно положить в стек несколько раз.
5. Вывод результата. После обхода всей карты счётчик содержит количество островов.

---
**Почему DFS, а не BFS?**

Оба обхода дают одинаковую сложность. DFS выбран потому, что его итеративная реализация через vector в роли стека максимально проста: не нужна отдельная очередь и её указатели. Для сеточных задач порядка 100×100 разница между DFS и BFS несущественна.

**Почему итеративный DFS, а не рекурсивный?**

Рекурсивный DFS на карте 100×100 в худшем случае (например, вся карта — сплошная суша в форме змейки) может уйти на глубину до 10 000 вызовов. При стандартном размере стека это, скорее всего, не переполнит стек, но итеративная версия надёжнее и не зависит от размера стека вызовов. Также итеративная версия работает быстрее за счёт отсутствия накладных расходов на вызовы функций.

**Почему используется vector?**

**vector** здесь оправдан по нескольким причинам:

1. vector<string> для хранения карты.
   - Позволяет читать строку целиком через cin >> map[i], что проще и быстрее ручного посимвольного чтения.
   - Автоматически управляет памятью — не нужно вручную выделять/освобождать двумерный массив.
   - Индексация map[i][j] такая же быстрая, как у обычного массива.
2. vector<pair<int, int>> в роли стека.
   - Даёт операции push_back и pop_back за O(1) — ровно то, что нужно для стека.
   - Не нужно писать собственный класс стека с ручным управлением памятью: это лишний код без выигрыша в производительности.
   - vector хранит данные в непрерывном блоке памяти, что даёт хорошую локальность кэша при обходе.
3. Альтернатива — статические массивы.
   - Можно было бы использовать int stack_r[10000], stack_c[10000] фиксированного размера, но это менее гибко: при изменении ограничений пришлось бы пересчитывать размер. vector растёт динамически и работает так же быстро.
   4. Осознанный отказ от других контейнеров STL.
   - std::stack был бы удобен, но он всё равно построен на deque и медленнее, чем vector в роли стека на малых объёмах.
   - std::queue для BFS — не нужен, так как выбран DFS.

## Оценка сложности

Пусть N — число строк, M — число столбцов.

- Временная сложность: O(N · M).
  - Каждая клетка карты посещается внешним циклом ровно один раз.
  - Каждая клетка суши кладётся в стек не более одного раза (благодаря пометке при добавлении).
  - Для каждой извлечённой клетки выполняется 4 проверки соседей — константное время.
  - Итого: O(N · M).
  - Пространственная сложность: O(N · M).
  - Карта хранится в vector<string> — O(N · M).
  - Стек в худшем случае (один большой остров) может содержать порядка O(N · M) элементов.
  - Итого: O(N · M).

При ограничениях N, M ≤ 100 максимальный размер карты — 10 000 клеток, что легко помещается в память и обрабатывается мгновенно.

## Проверка на примерах

Пример 1

Ввод:
```
3 4
.##.
####
..#.
```
Вывод: 1
- Все клетки # связаны между собой — один остров.

Пример 2

Ввод:
```
3 3
#.#
...
#.#
```
Вывод: 4
- Четыре отдельные клетки суши в углах, не связанные между собой — четыре острова.

Пример 3

Ввод:
```
1 1
#
```
Вывод: 1

Пример 4

Ввод:
```
2 2
..
..
```
Вывод: 0

# Итог

Решение использует итеративный DFS для подсчёта компонент связности на сетке. vector выбран как оптимальный компромисс между простотой, скоростью и безопасностью управления памятью. Временная и пространственная сложность — линейные по размеру карты, что с запасом укладывается в ограничения задачи.
