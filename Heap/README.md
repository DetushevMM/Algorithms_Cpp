# Куча (Max-Heap)

## Описание задачи

Необходимо реализовать абстрактную структуру данных Куча — максимальную двоичную кучу ("Max-Heap").

Куча должна поддерживать:
- "ShiftUp(index)" — восстановление свойства кучи движением элемента вверх;
- "ShiftDown(index)" — восстановление свойства кучи движением элемента вниз;
- "GetMax()" — получение максимального элемента;
- "PopMax()" — удаление максимального элемента;
- "Push(value)" — добавление нового элемента;
- "MakeHeap(array)" — построение кучи из существующего массива;
- "IsEmpty()" — проверка пустоты кучи.

Реализация выполнена без STL-контейнеров, с использованием собственного динамического массива.

---

## Свойство Max-Heap

Для каждого узла выполняется условие:
```
родитель >= левый ребёнок
родитель >= правый ребёнок
```
Поэтому максимальный элемент всегда находится в корне: `data_[0]`
```
Например, куча:

             8
           /   \
          5     1
         / \   / \
       -1  -6 -8 -9
```
соответствует массиву: `[8, 5, 1, -1, -6, -8, -9]`

Важно: куча не является отсортированным массивом. Гарантируется только отношение родителя к детям.

---

Хранение кучи в массиве

Так как бинарная куча является полным бинарным деревом, её удобно хранить непосредственно в массиве.

Для элемента с индексом "i":
```
left  = 2 * i + 1
right = 2 * i + 2
parent = (i - 1) / 2
```
Например:
```
Индекс:    0    1    2    3    4    5    6
           ↓    ↓    ↓    ↓    ↓    ↓    ↓
Массив:   [8,   5,   1,  -1,  -6,  -8,  -9]
```
Индекс "0" — корень.

Узлы с индексами: `i >= size / 2` являются листьями.

---

**Класс "Heap"**

Основные поля:
```
int* data_;
int capacity_;
int size_;

"data_"

Указатель на динамический массив элементов.

"size_"

Текущее количество элементов в куче.

"capacity_"
```
Количество элементов, для которых сейчас выделена память.

Например:
```
capacity = 8
size = 5
```
означает, что память выделена под 8 элементов, но куча содержит только 5.

---

**"ShiftUp(index)"**

Метод используется для восстановления свойства кучи после добавления элемента.

Новый элемент всегда сначала помещается в конец массива: `data_[size_] = value;`

На этой позиции он может нарушать свойство: родитель >= ребёнок. Поэтому элемент сравнивается с родителем.Если элемент больше родителя — они меняются местами. После обмена проверка продолжается уже с новой позиции элемента.

Алгоритм
```
пока элемент не является корнем:
    найти родителя

    если элемент > родителя:
        поменять их местами
        перейти к позиции родителя
    иначе:
        остановиться

Например, добавим "9":

До:

        8
       / \
      5   1
     /
   -1

После добавления:

        8
       / \
      5   1
     /
   -1
   /
  9

"9 > -1":

        8
       / \
      5   1
     /
    9

"9 > 5":

        8
       / \
      9   1
     /
    5

"9 > 8":

        9
       / \
      8   1
     /
    5
```
Свойство кучи восстановлено.

Сложность

Высота бинарного дерева: O(log n)

Поэтому: `ShiftUp = O(log n)`

---

**"ShiftDown(index)"**

Метод выполняет обратную операцию. Он используется, когда элемент оказался слишком маленьким относительно своих детей. Для текущего элемента необходимо найти наибольшего из трёх:
```
текущий элемент
левый ребёнок
правый ребёнок
```
Если один из детей больше текущего элемента, выполняется обмен с наибольшим ребёнком. После этого алгоритм продолжается с новой позиции. Почему именно с наибольшим ребёнком?
```
Рассмотрим:

       3
      / \
     8   5

Если поменять "3" с левым ребёнком:

       8
      / \
     3   5

свойство кучи восстановлено.

Если бы поменяли с "5":

       5
      / \
     8   3
```
получили бы нарушение: 5 < 8. Поэтому всегда выбирается больший ребёнок.

Алгоритм
```
пока есть дети:
    найти левого и правого ребёнка

    найти максимальный элемент среди:
        текущего узла
        левого ребёнка
        правого ребёнка
        если максимум находится не в текущем узле:
        поменять элементы
        перейти в позицию ребёнка
    иначе:
        остановиться
```
Сложность

За один шаг элемент перемещается на один уровень вниз.

Высота дерева: O(log n)

Следовательно: `ShiftDown = O(log n)`

---

**"Push(value)"**

Добавление элемента состоит из двух этапов.

1. Проверка свободного места

Если: size_ == capacity_ -> вызывается: Resize();

Размер массива увеличивается в два раза.

2. Добавление элемента

Новый элемент записывается в конец: `data_[size_] = value;`

После этого вызывается: `ShiftUp(size_);`, чтобы восстановить свойство кучи. В текущей реализации увеличение "size_" выполняется после "ShiftUp":
```
data_[size_] = value;
ShiftUp(size_);
++size_;
```
Это корректно, потому что "ShiftUp" работает с только что записанным элементом по индексу "size_", а границы массива для него не нужны.

Сложность

Само добавление — "O(1)" амортизированно.

"ShiftUp" — "O(log n)".

Итого: Push = O(log n)

---

**"Resize()"**

При заполнении массива создаётся новый массив:
```
int new_capacity = capacity_ * 2;
int* new_data = new int[new_capacity];
```
Все элементы копируются:
```
for (int i = 0; i < size_; ++i) {
    new_data[i] = data_[i];
}
```
После этого старый массив освобождается: `delete[] data_;` и указатель заменяется:
```
data_ = new_data;
capacity_ = new_capacity;
```
Удвоение ёмкости позволяет избежать перераспределения памяти при каждом "Push".

---

**"GetMax()"**

В Max-Heap максимальный элемент всегда находится в корне: return data_[0]; Поэтому дополнительного поиска не требуется.

Сложность: O(1)

В "main" перед вызовом "GetMax()" проверяется пустота:
```
if (heap.IsEmpty()) {
    std::cout << "None\n";
} else {
    std::cout << heap.GetMax() << '\n';
}
```
Таким образом, для пустой кучи выводится: None

---

**"PopMax()"**

Удаляется элемент "data_[0]".

Проблема заключается в том, что корень находится в начале массива, а остальные элементы нельзя просто сдвинуть. Поэтому используется стандартный приём:
1. последний элемент переносится в корень;
2. "size_" уменьшается;
3. новый корневой элемент опускается с помощью "ShiftDown".
```
data_[0] = data_[size_ - 1];
--size_;
ShiftDown(0);

Например:

До:

        8
       / \
      5   3
     / \
    1   2

После удаления "8":

        2
       / \
      5   3
     /
    1

Теперь "2 < 5", поэтому выполняется "ShiftDown":

        5
       / \
      2   3
     /
    1
```
Свойство кучи восстановлено.

Если куча пуста:
```
if (size_ == 0) {
    return;
}
```
ничего не происходит.

Сложность

PopMax = O(log n)

---

**"MakeHeap(array, n)"**
- Метод преобразует обычный массив в Max-Heap.
- void MakeHeap(int* array, int n)
- Сначала массив копируется во внутренний "data_".
- Затем выполняется построение кучи снизу вверх:
```
for (int i = size_ / 2 - 1; i >= 0; --i) {
    ShiftDown(i);
}
```
Начинаем с последнего узла, у которого есть дети, и постепенно движемся к корню.

---

Почему листья не обрабатываются. Например, для: [1, 2, 3, 4, 5, 6, 7]
```
дерево выглядит так:

          1
        /   \
       2     3
      / \   / \
     4   5 6   7
```
Элементы: 4, 5, 6, 7 являются листьями. У них нет детей, поэтому они уже являются корректными кучами из одного элемента. Первый элемент, который нужно обработать: `i = n / 2 - 1`

Для "n = 7": `i = 7 / 2 - 1 = 2`

## Алгоритм Флойда

Построение выполняется методом bottom-up heap construction, известным как алгоритм Флойда.

Для массива: [1, 2, 3, 4, 5, 6, 7]
```
сначала обрабатывается индекс "2":

      3
     / \
    6   7

"7" больше "3":

      7
     / \
    6   3

Затем индекс "1":

      2
     / \
    4   5

После "ShiftDown":

      5
     / \
    4   2

Затем обрабатывается корень:

      1
     / \
    5   7

"7" является максимальным ребёнком, поэтому:

      7
     / \
    5   1

После дальнейшего "ShiftDown" получается корректная Max-Heap:

          7
        /   \
       5     6
      / \   / \
     4   2 1   3
```
---

Почему "MakeHeap" работает за O(n)

Если для каждого элемента вызывать "Push", получится: `n × O(log n) = O(n log n)`
Но при построении снизу вверх большинство элементов находятся близко к листьям и могут опускаться только на небольшое расстояние.

Количество узлов быстро уменьшается с увеличением высоты:
```
примерно n/2 узлов → высота 0
примерно n/4 узлов → высота 1
примерно n/8 узлов → высота 2
...
```
Суммарная работа: O(n)

Поэтому "MakeHeap" значительно эффективнее последовательного добавления всех элементов через "Push".

---

**"IsEmpty()"**

Проверка выполняется по размеру: `return size_ == 0;`

Если: size_ == 0 - возвращается: true, иначе: false

Сложность: O(1)

---

**Работа "main"**
- Сначала считывается исходный массив:
```
N
a1
a2
...
aN
```
- Затем создаётся объект: Heap heap; и вызывается: `heap.MakeHeap(array, n);`
- После построения исходный временный массив больше не нужен: `delete[] array;`
- Затем считывается количество операций "M".

Для каждого запроса выбирается соответствующий метод:

|Команда| Метод| Вывод|
|-------|------|------|
"GetMax"| "GetMax()"| максимум или "None"
"PopMax"| "PopMax()"| ничего
"Push value"| "Push(value)"| ничего
"IsEmpty"| "IsEmpty()"| "TRUE" / "FALSE"

## Управление памятью

Класс самостоятельно управляет динамическим массивом.

Конструктор:
```
Heap() : capacity_(4), size_(0) {
    data_ = new int[capacity_];
}
```
выделяет начальную память.

Деструктор:
```
~Heap() {
    delete[] data_;
}
```
освобождает её.

При "Resize()" старый массив также удаляется после копирования элементов.

Таким образом, жизненный цикл внутреннего массива полностью контролируется классом "Heap".

# Итог

- Реализована Max-Heap на основе собственного динамического массива.
- Ключевые операции работают следующим образом:
```
Push
  ↓
добавить в конец
  ↓
ShiftUp

PopMax
  ↓
последний элемент → корень
  ↓
ShiftDown

MakeHeap
  ↓
скопировать массив
  ↓
ShiftDown от последнего родителя к корню
```
Главные свойства реализации:
- максимум всегда находится в "data_[0]";
- "Push" восстанавливает структуру через "ShiftUp";
- "PopMax" восстанавливает её через "ShiftDown";
- "MakeHeap" использует алгоритм Флойда и работает за "O(n)";
- внутренний массив автоматически расширяется при заполнении;
- структура не использует STL.
