# Дороги между городами

Решение задачи о поиске кратчайшего пути между двумя городами во взвешенном неориентированном графе.

## Условие задачи

Есть N городов и M двусторонних дорог. Для каждой дороги известно время движения по ней. Все времена положительны.
Необходимо найти минимальное суммарное время, необходимое чтобы добраться из города S в город T.

Формат ввода:
- В первой строке записаны четыре целых числа N, M, S, T.
- В следующих M строках записаны три целых числа u, v, w — дорога соединяет города u и v, а время движения по ней равно w.

Формат вывода:
- Выведите минимальное время пути из S в T. Если добраться невозможно, выведите -1.

Ограничения
```
· 1 ≤ N ≤ 10^5
· 0 ≤ M ≤ 2·10^5
· 1 ≤ S, T ≤ N
· 1 ≤ w ≤ 10^9
· Петли отсутствуют
```
**Примеры**

Пример 1
```
Ввод:
5 6 1 5
1 2 4
1 3 2
3 2 1
2 4 5
3 4 8
4 5 3
```
Вывод: 11

Пример 2
```
Ввод:
4 2 1 4
1 2 7
3 4 1
```
Вывод: -1

Пример 3
```
Ввод:
3 3 2 2
1 2 10
2 3 20
1 3 5
```
Вывод: 0

## Идея решения

Задача сводится к классическому поиску кратчайшего пути в взвешенном графе с неотрицательными весами рёбер. Поскольку все времена движения положительны, применим алгоритм Дейкстры.

Почему именно Дейкстра?
- Веса неотрицательны — это ключевое условие применимости алгоритма Дейкстры. При наличии отрицательных рёбер потребовался бы Беллман–Форд или SPFA.
- Один источник, одна цель — достаточно запустить алгоритм из S и остановиться при извлечении T из очереди с приоритетами.
- Плотность графа — при `M ≤ 2·10^5` и `N ≤ 10^5` разреженный граф, что делает реализацию с бинарной кучей эффективнее матричной версии за O(N²).

**Альтернативы и почему они не подходят**

|Алгоритм| Проблема|
|--------|---------|
Беллман–Форд| O(N·M) — слишком медленно при данных ограничениях
Флойд–Уоршелл| O(N³) — неприемлемо при N = 10^5
BFS| Работает только для невзвешенных графов
A*| Требует эвристику, не всегда применима

### Алгоритм Дейкстры

*Принцип работы*

1. Инициализируем массив расстояний dist: dist[S] = 0, для остальных — «бесконечность».
2. Помещаем S в очередь с приоритетом (минимальную кучу) с ключом 0.
3. Пока куча не пуста:
   - Извлекаем вершину u с минимальным расстоянием.
   - Если u уже обработана — пропускаем (устаревшая запись).
   - Помечаем u как обработанную; если u == T — завершаем.
   - Для каждого соседа v по ребру веса w: если `dist[u] + w < dist[v]`, обновляем dist[v] и добавляем v в кучу.
4. Ответ — dist[T], либо -1, если значение осталось бесконечным.

Корректность:
- Алгоритм опирается на жадный инвариант: в момент извлечения вершины из минимальной кучи её расстояние окончательно и не может быть улучшено, поскольку все веса неотрицательны и любая альтернативная дорога была бы не короче.

Обработка устаревших записей:
- Одна вершина может попасть в кучу несколько раз при улучшении расстояния. Вместо операции decrease-key используется более простая и надёжная техника «ленивого удаления»: при извлечении вершины проверяем флаг visited; если она уже обработана — просто пропускаем запись. Это увеличивает размер кучи до O(M), но упрощает реализацию.

Крайние случаи:
- `S == T` — расстояние инициализировано нулём, ответ 0, независимо от структуры графа.
- Несвязный граф / нет пути — dist[T] остаётся INF, выводим -1.
- `M == 0` — все расстояния, кроме dist[S], остаются INF.
- Максимальный путь — до `(N-1)·10^9 ≈ 10^14`, поэтому для расстояний используется long long (тип int переполнится).

## Структуры данных

Очередь с приоритетом - Реализована вручную как бинарная минимальная куча на массиве, поскольку требуется минимальный набор библиотек. Поддерживаемые операции:
- push(dist, vertex) — добавление элемента за O(log n) с просеиванием вверх.
- pop() — извлечение минимума за O(log n) с просеиванием вниз.
- empty() — проверка на пустоту за O(1).

Список смежности

Граф хранится как массив «голов» односвязных списков Edge* head[N+1]. Каждое ребро добавляется дважды (для u → v и v → u), поскольку дороги двусторонние. Такое представление:
- Экономит память по сравнению с `vector<vector<pair<int,int>>>`.
- Позволяет обойтись без стандартных контейнеров.
- Даёт суммарный объём O(N + M). Оценка сложности

*Пусть N — число вершин, M — число рёбер.*

|Компонент| Время| Память|
|---------|------|-------|
Построение графа| O(M)| O(N + M)
Инициализация массивов| O(N)| O(N)
Куча (всего операций)| O((N + M) log M)| O(M)
Обход рёбер| O(M)| суммарно —
Итого| O((N + M) log N)| O(N + M)

Логарифм берётся по размеру кучи, который не превосходит O(M). Для данных ограничений (N = 10^5, M = 2·10^5) алгоритм укладывается в доли секунды.

## Особенности реализации
- Отсутствие `<algorithm>` — все служебные операции (обмен, просеивание) написаны вручную.
- Отсутствие STL-контейнеров — куча, список смежности и массивы метрик реализованы на «сырых» указателях и new[]/delete[].
- Ранний выход — как только T извлечена из кучи, цикл прерывается: дальнейшие расстояния нас не интересуют.
- Ручное освобождение памяти — граф, куча, массивы dist/visited очищаются в конце.
