# Самый дешёвый путь

### Условие задачи

В компьютерной сети есть N узлов и M направленных соединений. Передача данных по каждому соединению имеет положительную стоимость.
Нужно передать пакет из узла S в узел T. Найти минимальную стоимость передачи и восстановить любой маршрут, имеющий эту стоимость.

Формат ввода:
- Первая строка: N M S T
- Следующие M строк: u v w — направленное ребро из u в v со стоимостью w

Ограничения
```
· 1 ≤ N ≤ 10^5
· 0 ≤ M ≤ 2·10^5
· 1 ≤ S, T ≤ N
· 1 ≤ w ≤ 10^9
· Петли отсутствуют
```
Формат вывода:
- Если путь невозможен — вывести -1.
- Иначе:
  - первая строка — минимальная стоимость D;
  - вторая строка — количество вершин K в маршруте;
  - третья строка — K номеров вершин от S до T.

Если оптимальных маршрутов несколько — допустим любой.

---

## Идея решения

Задача — классический поиск кратчайшего пути во взвешенном ориентированном графе с неотрицательными весами. Все веса строго положительны (w ≥ 1), что открывает выбор между двумя основными подходами:

|Алгоритм| Сложность| Когда применим|
|--------|----------|---------------|
Дейкстра| O((N + M) log N)| Веса неотрицательны
Беллман–Форд| O(N · M)| Есть отрицательные веса

При `N = 10^5` и `M = 2·10^5` Беллман–Форд дал бы до `2·10^10` операций — это неприемлемо. Поэтому выбран алгоритм Дейкстры.

Почему Дейкстра корректен здесь:
- Ключевое свойство: как только вершина извлекается из очереди с минимальным расстоянием, это расстояние окончательное. Оно работает только при неотрицательных весах — что гарантировано условием (w ≥ 1). Если бы веса могли быть отрицательными, жадный выбор «ближайшей» вершины был бы неверным.

---

# Структуры данных

*Граф*
- Хранится как список смежности: `vector<vector<Edge>>`, где `Edge = {to, w}`.
- Почему не матрица смежности: при `N = 10^5` матрица заняла бы `10^10` ячеек — невозможно. Список смежности использует `O(N + M)` памяти, что при `M ≤ 2·10^5` вполне приемлемо.

Приоритетная очередь:
- Используется `priority_queue` с компаратором `greater — это min-heap`, из которого всегда извлекается вершина с наименьшим текущим расстоянием.

Почему не обычная очередь (BFS): BFS работает только для невзвешенных графов, где все рёбра «стоят одинаково». Здесь веса разные, поэтому нужен именно приоритет по расстоянию.

Массив расстояний: `vector<long long> dist(N + 1, INF)`, где `INF = 10^18`.

Почему long long, а не int: максимальная длина пути — это `(N − 1) · w_max ≈ 10^5 · 10^9 = 10^14`, что не помещается в 32-битный int.

Почему `INF = 10^18`, а не LLONG_MAX: при LLONG_MAX операция dist[u] + w могла бы переполниться. Значение 10^18 заведомо больше любого реального пути (10^14), но при этом `10^18 + 10^9` всё ещё помещается в long long. Это стандартный приём «безопасной бесконечности».

Массив предков; `vector<int> parent(N + 1, 0)` — для каждой вершины хранит, из какой вершины в неё пришли по кратчайшему пути. Нужен для восстановления маршрута.

---

### Ход алгоритма

1. Инициализация: dist[S] = 0, все остальные — INF. В очередь кладём (0, S).
2. Основной цикл: пока очередь не пуста:
   - извлекаем вершину u с минимальным d;
   - если d > dist[u] — это устаревшая запись, пропускаем (такие «дубликаты» появляются, когда мы улучшаем расстояние до вершины несколько раз и каждый раз кладём её в очередь);
   - для каждого ребра u → v проверяем, улучшает ли новый путь dist[u] + w текущее dist[v]. Если да — обновляем dist[v], записываем parent[v] = u и кладём (dist[v], v) в очередь.
3. Проверка достижимости: если dist[T] == INF — путь не существует, выводим -1.
4. Восстановление пути: идём от T по parent до S, собирая вершины в вектор. Затем разворачиваем вектор вручную (чтобы не подключать `<algorithm>`).
5. Вывод: стоимость, количество вершин, сам маршрут.

Простой случай `S == T`
- Алгоритм обрабатывает его автоматически: dist[S] = 0, цикл восстановления сразу завершается, вывод — 0, 1, S. Отдельная проверка не нужна.

## Оценка сложности

|Ресурс| Сложность| Пояснение|
|------|----------|----------|
Время| O((N + M) log N)| Каждая вершина и каждое ребро обрабатываются ограниченное число раз; каждое обновление — O(log N) на операцию с кучей
Память| O(N + M)| Список смежности + массивы dist и parent. При заданных ограничениях `(N ≤ 10^5, M ≤ 2·10^5)` это укладывается в типичный лимит времени порядка 1 секунды.

---

Почему именно такое решение

1. Дейкстра, а не Беллман–Форд — из-за неотрицательных весов и больших ограничений. Беллман–Форд асимптотически хуже и здесь не нужен.
2. Куча вместо линейного поиска минимума — «наивная» Дейкстра за O(N²) дала бы 10^10 операций при N = 10^5. Куча снижает это до O((N + M) log N).
3. long long для расстояний — иначе переполнение на длинных путях.
4. INF = 10^18 вместо LLONG_MAX — защита от переполнения при сложении.
5. Список смежности вместо матрицы — экономия памяти.
6. Ручной разворот пути и минимум заголовков — по требованию задачи: только `<iostream>, <vector>, <queue>`, без `<algorithm>` и `<climits>`.
7. Проверка d > dist[u] — стандартный приём для неактуальных записей в куче; без него алгоритм всё равно корректен, но делает лишнюю работу.

Тестовые примеры

Пример 1
```
Ввод:
5 7 1 5
1 2 4
1 3 2
3 2 1
2 4 5
3 4 8
4 5 3
2 5 20

Вывод:
11
5
1 3 2 4 5
```
Кратчайший путь: `1 → 3 → 2 → 4 → 5`, стоимость `2 + 1 + 5 + 3 = 11`.

Пример 2
```
Ввод:
4 2 1 4
1 2 7
3 4 1
```
Вывод: -1 (Из 1 нельзя попасть в 4).

Пример 3
```
Ввод:
3 3 2 2
1 2 10
2 3 20
1 3 5
```
Вывод:
```
0
1
2
```
Старт совпадает с финишем — путь нулевой длины из одной вершины.
