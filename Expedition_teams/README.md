# Экспедиционные группы

## Условие задачи

В туристическом лагере находятся N участников. Некоторые пары участников знакомы друг с другом.

Если два человека знакомы, они могут передать информацию напрямую. Кроме того, информация может передаваться через цепочку знакомых.

Участники относятся к одной группе, если любой участник группы может передать информацию любому другому через цепочку знакомств.

Задача: определить количество независимых групп участников.

Формат ввода:
- Первая строка: два целых числа N и M — количество участников и количество пар знакомых.
- Следующие M строк: пары u v, означающие, что участники u и v знакомы.
- Знакомство взаимно. Петель и повторяющихся пар нет.

Ограничения:
```
1 ≤ N ≤ 1000
0 ≤ M ≤ 5000
```
Формат вывода:
- Одно целое число — количество независимых групп участников.

Пример

Ввод:
```
5 3
1 2
2 3
4 5
```
Вывод: 2

Пояснение: Участники {1, 2, 3} образуют одну группу (1 знаком с 2, 2 знаком с 3, значит 1 связан с 3 через 2). Участники {4, 5} образуют вторую группу. Участник 5 не связан с первой группой.

---

## Идея решения

Задача сводится к классической задаче поиска числа компонент связности в неориентированном графе:
- Вершины — участники лагеря.
- Рёбра — знакомства между ними.
- Группа — компонента связности: множество вершин, между любыми двумя из которых существует путь.

Так как знакомство взаимно, граф неориентированный. Ответ — количество компонент связности.

---

## Алгоритм

Используется обход в глубину (DFS) в итеративной форме.
1. Построение графа.
      - Считываем M пар и для каждой добавляем ребро в обе стороны (граф неориентированный). 
      - Храним граф в виде списка смежности: для каждой вершины u — список всех её соседей.
2. Инициализация.
      - Заводим массив visited размера N + 1, изначально все false. Счётчик групп groups = 0.
3. Обход всех вершин.
      - Для каждой вершины start от 1 до N:
   - Если она уже посещена — пропускаем.
   - Иначе это начало новой компоненты: увеличиваем groups.
   - Запускаем DFS из start, помечая все достижимые вершины как посещённые.
4. Итеративный DFS.
      - Вместо рекурсии используем vector<int> в роли стека:
   - Кладём start, помечаем посещённой.
   - Пока стек не пуст: берём верхнюю вершину, перебираем её соседей, непосещённых помечаем и кладём в стек.
5. Вывод.
      - Печатаем groups.

## Оценка сложности

Пусть N — число вершин, M — число рёбер.

|Ресурс| Оценка| Пояснение|
|------|-------|----------|
Время| O(N + M)| Каждая вершина помечается посещённой один раз; каждое ребро просматривается дважды (по разу с каждой стороны).
Память| O(N + M)| Список смежности хранит 2M записей; массивы visited и стек — по O(N).

При заданных ограничениях (N ≤ 1000, M ≤ 5000) решение работает мгновенно.

---

**Почему DFS, а не BFS?**

Оба алгоритма дают одинаковый результат и одинаковую сложность O(N + M). DFS выбран потому, что:
- Итеративная реализация через vector в роли стека короче и нагляднее, чем очередь для BFS.
- Нет необходимости хранить порядок обхода — важна лишь достижимость.

Почему итеративный DFS, а не рекурсивный?
- Рекурсивный DFS при неблагоприятной структуре графа (например, «бамбук» из 1000 вершин) может привести к глубокой рекурсии и переполнению стека вызовов.
- Итеративный вариант полностью контролирует используемую память и не зависит от размера системного стека.

**Почему vector, а не ручная реализация динамических массивов?**

1. Список смежности.
      - Заранее неизвестно, сколько соседей у каждой вершины. vector<vector<int>> позволяет динамически наращивать списки рёбер без ручного realloc и без риска утечек памяти.
2. Стек для DFS.
      - vector<int> с операциями push_back / pop_back — это готовый LIFO-контейнер с амортизированной сложностью O(1) на операцию. 
      - Ручная реализация стека на «сырых» массивах потребовала бы отслеживать ёмкость, обрабатывать переполнение и освобождать память — всё это лишний код без выигрыша в скорости.
      3. Массив visited.
      - Размер известен заранее (N + 1), поэтому здесь достаточно vector<bool> — компактного битового массива с индексацией от 1.
4. Безопасность и читаемость.
      - vector автоматически управляет памятью, что исключает утечки и выход за границы при аккуратном использовании push_back и индексации. Итоговый код проще проверять и сопровождать.

---

Проверка на примере

Граф: рёбра (1–2), (2–3), (4–5).
- Старт с вершины 1 → DFS посещает {1, 2, 3}. groups = 1.
- Вершины 2, 3 уже посещены — пропускаем.
- Старт с вершины 4 → DFS посещает {4, 5}. groups = 2.
- Вершина 5 посещена — пропускаем.

Ответ: 2.

## Крайние случаи

|Случай| Поведение|
|------|----------|
M = 0| Каждый участник — отдельная группа. Ответ: N.
Граф — одна компонента| Ответ: 1.
Изолированные вершины + компоненты| Каждая изолированная вершина даёт +1 к ответу.
Максимальные N = 1000, M = 5000| Решение укладывается в лимиты с большим запасом.
